# 사물 인지 — 박스 치고 이름표 붙이기

카메라·동영상·이미지에서 물체를 찾아 **박스를 그리고 무엇인지 태그**를 단다.
COCO 80종(사람·자동차·의자·노트북·컵 …)을 인식하고,
`world` 백엔드를 쓰면 **찾을 것을 글자로 적어** 80종 밖의 물체도 찾는다.

쓰는 방법이 세 가지다.

```bash
python detect_gui.py                      # GUI — 옵션을 화면에서 고른다
```
```bash
python phone_server.py                    # 휴대폰 — 폰 브라우저로 접속
```
```bash
python detect.py                          # 명령줄 — 카메라 0번 실시간
python detect.py --source photo.jpg       # 이미지 한 장
python detect.py --source clip.mp4        # 동영상
```

처음이면 GUI 가 편하다. 반복 작업이나 일괄 처리는 명령줄이 낫다.
돌아다니면서 쓰려면 휴대폰이다.

## 휴대폰에서 쓰기

```bash
python phone_server.py
```

띄우면 주소가 나온다. 폰 브라우저에서 그 주소를 열고 **공유 → 홈 화면에 추가**
하면 앱 아이콘이 생기고 전체화면으로 뜬다(PWA). 설치할 것은 없다.

```
================================================================
  폰 브라우저에서 열 주소

      https://192.168.43.12:8443/        <- 핫스팟 또는 가정용 공유기
      https://10.60.6.66:8443/           <- 기관/사내망 (유선일 가능성)
================================================================
```

주소가 여러 개면 **폰과 같은 망에 있는 것**을 쓴다. 서버는 가진 IPv4 주소를
전부 찾아 보여주고, 어떤 망인지 짐작해 표시해 준다.

### 폰과 PC 를 같은 망에 두기

이게 이 방식의 유일한 전제다. 유선만 쓰는 PC 라면 아래 중 하나로 붙인다.

| 방법 | 하는 법 | 비고 |
|---|---|---|
| **폰 핫스팟 + PC WiFi** | 폰에서 핫스팟을 켜고, PC 작업표시줄 WiFi 에서 그 핫스팟에 접속 | 가장 간단. 유선은 그대로 두면 된다 |
| **USB 테더링** (안드로이드) | USB 로 연결하고 폰 설정에서 USB 테더링 켜기 | 무선보다 안정적, 배터리도 충전된다 |
| 같은 WiFi 에 둘 다 접속 | PC WiFi 를 폰과 같은 AP 에 연결 | 기관 WiFi 는 기기 간 통신을 막는 경우가 많다 |

핫스팟에 붙으면 **PC 의 인터넷 경로가 폰 쪽으로 넘어갈 수 있다**(셀룰러 데이터를
쓴다). 폰↔PC 사이 검출 트래픽 자체는 로컬이라 데이터를 쓰지 않지만, 신경 쓰이면
잠깐 쓰는 동안 폰의 모바일 데이터를 꺼 두면 된다.

망을 바꾼 뒤에는 **서버만 다시 띄우면 된다.** 주소가 바뀐 것을 알아채고
인증서를 다시 만든다(인증서에는 접속 주소가 들어 있어야 한다).

### 구조 — 폰은 카메라, PC 는 추론

폰에서 직접 추론하려면 모델을 변환해 얹어야 하고 성능도 크게 떨어진다.
이 PC 에 RTX 5070 Ti 와 이미 만든 검출기가 있으므로 이렇게 나눴다.

```
폰 카메라 → JPEG 한 장 → (WiFi) → PC 에서 추론 → 상자 좌표 JSON → 폰이 그린다
```

덕분에 **폰에서 검출기를 바꾸고 YOLO-World 프롬프트도 고칠 수 있다.**
`detect.py` 의 검출기를 그대로 쓰므로 기능 차이가 없다.

### 폰 화면에서 할 수 있는 것

| | |
|---|---|
| 시작 / 정지 | 실시간 검출 |
| 카메라 전환 | 후면 ↔ 전면 |
| 목록 | 지금 찾은 것들을 신뢰도와 함께 |
| 설정 | 검출기, 프롬프트(world), 신뢰도, 보내는 크기, 이름표 언어 |

화면 위쪽에 상태·fps·추론시간·검출 개수·모델이 뜬다.

### 처음 한 번만 — 인증서 경고

브라우저는 **HTTPS 가 아니면 카메라를 열어주지 않는다.** 그래서 서버가 자체
서명 인증서를 만들어 TLS 로 뜬다(`certs/` 에 생긴다. 크롬·사파리가 요구하는
`subjectAltName` 에 LAN IP 를 넣어 둔다).

폰에서 처음 열면 **"연결이 비공개가 아닙니다"** 경고가 나온다.
**고급 → 계속 진행**을 누르면 된다. 한 번 넘기면 그 폰은 다시 안 묻는다.
공인 인증기관 서명이 아니라서 나오는 경고이고, 통신은 이 공유기 안에서만 오간다.

### 옵션

```bash
python phone_server.py --backend world --prompt "door=문, mug=머그컵"
python phone_server.py --port 9000
python phone_server.py --http          # TLS 없이 (PC localhost 확인용,
                                       #  폰에서는 카메라가 안 열린다)
```

### 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 페이지가 안 열림 | 폰과 PC 가 **같은 망**에 있는지 (위의 표 참고). 기관 WiFi 는 기기 간 통신을 막는 경우가 있다 |
| 주소가 여러 개 | 폰과 같은 망 쪽을 쓴다. 핫스팟이면 보통 `192.168.x` 나 `172.20.10.x` |
| 페이지는 열리는데 카메라가 안 켜짐 | `https://` 로 열었는지. `http://` 면 브라우저가 막는다 |
| 연결 문제 표시 | PC 에서 서버 창이 살아 있는지, 방화벽이 python 인바운드를 막는지 |
| 느림 | 설정에서 **보내는 크기**를 480 으로 낮춘다 |

## GUI

```bash
python detect_gui.py
```

왼쪽에서 고르고 **시작**을 누르면 오른쪽에 영상과 검출 목록이 나온다.

| 묶음 | 고를 수 있는 것 |
|---|---|
| 입력 | 카메라(번호 자동 검색·다시 찾기) 또는 파일(이미지·동영상), 해상도 |
| 검출기 | auto / yolo / **world** / frcnn / frcnn50 / ssdlite, 가중치, 장치(auto·cuda·cpu) |
| 표시 | 신뢰도 슬라이더, 이름표 한글·영문, 글자 크기, 신뢰도 표시 여부 |
| 찾을 물체 | COCO 80종에서 골라 그것만 표시 (안 고르면 전부) |
| 찾을 것 (world) | 찾고 싶은 것을 글자로 적는 칸으로 바뀐다 |
| 저장 | 화면 저장, JSON 저장, 영상 녹화 |

검출기를 `world` 로 바꾸면 클래스 목록 자리가 **프롬프트 입력칸**으로 바뀌고,
신뢰도가 0.15 로 자동 조정된다(open-vocabulary 는 점수가 낮게 나온다).
**프롬프트 적용**을 누르면 돌아가는 중에도 0.2초 안에 갈아끼운다 — 모델을
다시 만들지 않는다.

- **신뢰도 슬라이더는 돌아가는 중에 바로 반영된다.** 검출기를 다시 만들지 않는다.
- **찾을 물체**를 고르면 나머지는 화면·목록·JSON 에서 전부 빠진다.
  예를 들어 `휴대폰`만 고르면 사람은 잡혀도 표시되지 않는다.
- 검출기·가중치·장치를 바꾸면 다음 **시작** 때만 새로 만든다. 같은 설정이면
  이미 올라간 모델을 그대로 쓰므로 다시 기다리지 않는다.
- 오른쪽 아래 목록에 물체·신뢰도·박스 좌표가 실시간으로 나오고,
  맨 아래 상태줄에 모델·장치·추론시간·fps·검출 요약이 나온다.

수집과 추론은 작업 스레드에서 하고 tkinter 는 메인 스레드에서만 건드린다.
슬라이더 값도 GUI 스레드가 복사해 둔 것을 워커가 읽는다 — Tcl 은 스레드
안전하지 않아서 워커가 tkinter 변수를 직접 읽으면 프로세스가 죽는다.

## 필요한 것

이 PC 에는 이미 다 깔려 있다.

| | |
|---|---|
| torch 2.13 + CUDA | RTX 5070 Ti 로 GPU 추론 |
| ultralytics 8.4 | YOLO — 기본 검출기 |
| torchvision 0.28 | 사전학습 COCO 검출 모델 (대체 경로) |
| opencv-python 4.13 | 카메라·영상 입출력, 박스 그리기 |
| pillow | 한글 이름표 렌더링 |

가중치는 **처음 한 번만** 자동으로 내려받는다
(yolo11n 5 MB, ssdlite 13 MB, frcnn50 167 MB).

## 80종 밖의 물체 찾기 — `world` (open-vocabulary)

COCO 80종에 없는 것을 찾아야 하면 이걸 쓴다. 학습도 라벨링도 필요 없다.
**찾고 싶은 것을 글자로 적으면** 그걸 찾는다.

```bash
python detect.py --backend world --prompt "door, stairs, safety helmet, mug"
```

화면에 한글로 보고 싶으면 `영어=한글` 로 적는다. CLIP 에는 영어가 가고
이름표에는 한글이 나온다.

```bash
python detect.py --backend world --prompt "coat rack=옷걸이, window=창문, eyeglasses=안경"
```

### 실측 — COCO 에 없는 것들이 잡힌다

같은 사진, `yolov8s-worldv2.pt`, conf 0.15:

```
넥타이  51%   창문  43%   창문  39%   안경  37%   옷걸이  35%
사람    46%   셔츠  22%   셔츠  21%   창문  21%
```

`창문`·`안경`·`셔츠`·`옷걸이` 는 COCO 80종에 아예 없는 개념이다.
추론은 5.6 ms 로 YOLO11n 과 같은 속도다.

### 알아둘 점

- **영어 프롬프트를 쓴다.** CLIP 텍스트 인코더를 타기 때문에 한글은 잘 안 맞는다.
  표시만 한글로 하려면 위의 `영어=한글` 표기를 쓴다.
- **점수가 전반적으로 낮다.** 고정 어휘 모델이 99% 를 주는 것도 여기서는 40%대다.
  `--conf` 를 안 주면 자동으로 0.15 를 쓴다. 0.1~0.25 사이에서 조절한다.
- 흔한 사물은 잘 잡지만, 학습 데이터에 거의 없던 개념(특정 부품, 공정 결함)은
  들쭉날쭉하다. 그런 건 직접 학습시키는 편이 낫다.
- 프롬프트를 구체적으로 적을수록 잘 맞는다. `bag` 보다 `black leather handbag`.
- 첫 `set_classes` 는 CLIP 을 올리느라 1~2초, 이후는 0.1초 안쪽이다.
  처음 쓸 때 가중치(약 25 MB)와 CLIP(약 338 MB)을 자동으로 내려받는다.

더 넓히려면 `yolov8m-worldv2.pt` / `yolov8l-worldv2.pt` 로 키우면 된다.

## 검출기 고르기

기본값은 `auto` 다. ultralytics 가 있으면 YOLO 를, 없으면 `ssdlite` 를 쓴다.

```bash
python detect.py                     # auto = yolo11n
python detect.py --backend frcnn50   # 가장 정확
python detect.py --weights yolo11s.pt  # 조금 더 정확한 YOLO
```

### 실측 — 같은 사진, 같은 문턱값(0.5), 20회 평균, 워밍업 후

RTX 5070 Ti, 640×480:

| `--backend` | 모델 | 추론 | fps | 찾은 것 |
|---|---|---:|---:|---|
| `yolo` (기본) | YOLO11n | **5.3 ms** | 189 | 사람, 넥타이 |
| `world` | YOLO-World s | 5.6 ms | 179 | 적은 대로 (창문·안경·옷걸이 …) |
| `yolo --weights yolo11s.pt` | YOLO11s | 6.2 ms | 162 | 사람, 넥타이 |
| `frcnn` | Faster R-CNN MobileNetV3 | 12.7 ms | 79 | 사람, 넥타이 |
| `frcnn50` | Faster R-CNN ResNet50 v2 | 34.0 ms | 29 | 사람, 넥타이 x2, 핸드백 |
| `ssdlite` | SSDLite320 MobileNetV3 | 38.2 ms | 26 | 사람 |

**`ssdlite` 는 이름과 달리 GPU 에서 가장 느리다.** 작은 연산이 많은 모바일용
구조라 GPU 를 못 채운다. CPU 로 돌리거나 의존성을 최소로 줄일 때만 의미가 있다.

### 실측 — 실제 카메라 60프레임, 문턱값 0.4

| | 추론 | fps | 검출 | 신뢰도 평균 |
|---|---:|---:|---|---:|
| `yolo` | **7 ms** | 153 | 60/60 프레임에서 사람 | **90.2%** |
| `ssdlite` | 28 ms | 36 | 60/60 프레임에서 사람 | 62.7% |

둘 다 놓치지 않지만 YOLO 가 4배 빠르고 신뢰도가 훨씬 높다. 그래서 기본값이다.

작은 물체까지 최대한 긁어모아야 하면 `frcnn50` 이 여전히 가장 많이 찾는다
(위 표에서 유일하게 핸드백과 두 번째 넥타이를 잡았다).

## 실행 중 단축키

| 키 | 동작 |
|---|---|
| `q` 또는 `ESC` | 종료 |
| `space` | 일시정지 |
| `s` | 지금 화면을 `snapshot_날짜시각.jpg` 로 저장 |
| `[` `]` | 신뢰도 문턱값 -0.05 / +0.05 |
| `l` | 이름표 한글 ↔ 영문 |
| `h` | 도움말 표시 |

화면 왼쪽 위에 모델·장치·문턱값·추론시간·fps·검출 개수가 나온다.

## 옵션

```bash
python detect.py --list-cameras           # 쓸 수 있는 카메라 번호 확인
python detect.py --weights yolo11s.pt     # 더 큰 YOLO (m/l/x 도 됨)
python detect.py --backend world --prompt "door=문, mug=머그컵"   # 글자로 지정
python detect.py --conf 0.3               # 문턱값 (기본 0.5, 낮추면 더 많이 잡음)
python detect.py --lang en                # 이름표를 영문 COCO 이름으로
python detect.py --device cpu             # GPU 대신 CPU
python detect.py --source a.mp4 --save out.mp4    # 결과 영상 저장
python detect.py --source a.jpg --json r.json     # 결과를 JSON 으로
python detect.py --source a.mp4 --no-window --max-frames 100   # 창 없이 배치 처리
```

`--json` 결과는 이렇게 생겼다.

```json
{
  "source": "photo.jpg",
  "data": [
    {"label": "person", "score": 0.9993, "box": [46.0, 134.4, 494.2, 479.0]},
    {"label": "tie",    "score": 0.9851, "box": [251.5, 410.2, 319.3, 480.0]}
  ]
}
```

`label` 은 영문 원본 이름이다. 뒷단에서 쓰기 좋도록 화면 표시(한글)와 분리했다.

## 구성

| 파일 | 역할 |
|---|---|
| `phone_server.py` | 휴대폰용 HTTPS 서버 (표준 라이브러리만 씀) |
| `phone.html` | 휴대폰 화면 (PWA) |
| `detect_gui.py` | GUI — 옵션 선택, 실시간 미리보기, 검출 목록 |
| `detect.py` | 본체 — 입력, 검출, 그리기, 저장. 명령줄로도 쓴다 |
| (가중치) | `yolo11n.pt` 는 실행 폴더에, torchvision 것은 `~/.cache/torch` 에 받힌다 |
| `coco_ko.py` | COCO 클래스 영문 → 한글 표 (+ world 프롬프트 별칭) |

GUI 는 `detect.py` 의 검출기·그리기를 그대로 가져다 쓴다. 검출 로직은 한 곳에만
있으므로 `detect.py` 를 고치면 GUI 도 같이 바뀐다.

`detect.py` 의 검출기는 `__call__(frame_bgr, conf) -> list[Detection]` 하나만
지키면 되므로, 직접 학습한 모델을 붙일 때도 그 인터페이스만 맞추면 된다.

## 알아둘 점

- 카메라는 `--list-cameras` 로 번호를 먼저 확인한다. 이 PC 는 0번이 잡힌다
  (640×480 @ 30 fps, DSHOW 백엔드).
- 윈도우는 OpenCV 캡처 백엔드가 환경마다 갈린다. `open_camera()` 가
  DSHOW → MSMF → 기본 순으로 시도한다.
- 한글 이름표는 OpenCV 로 못 그린다(`putText` 에 한글 글리프가 없어 네모로
  나온다). 그래서 한글일 때만 프레임을 PIL 로 한 번 넘겨 라벨을 한꺼번에
  그리고 되돌린다 — 프레임당 왕복 1회로 끝낸다.
- **폰 쪽 프레임 캡처는 `canvas.toBlob` 이 아니라 동기 `toDataURL` 을 쓴다.**
  `toBlob` 은 콜백이 언제 불릴지 환경에 달려 있어서, 측정해 보니 크기·포맷과
  무관하게 한 장에 1010 ms 씩 걸렸다(64x64 도 1280x720 도 똑같이). 같은 조건에서
  `toDataURL` 은 2~3 ms 다. 이것만 바꿔서 1 fps → 118 fps 가 됐다.
- 캔버스는 크기를 바꾸면 내용이 지워진다. 그래서 화면 회전·패널 여닫기 때
  마지막 결과를 다시 그려 준다. 안 그러면 멈춘 상태에서 상자만 사라진다.
- 첫 프레임은 CUDA 초기화 때문에 느리다(1~2초). 화면과 종료 시 요약의 fps 는
  **최근 30장 평균**이라, 30장 이하로 짧게 돌리면 워밍업이 그대로 섞여
  실제보다 느리게 나온다. 속도를 재려면 최소 60장은 돌린다.
- 고정 어휘 백엔드는 COCO 80종만 잡는다. 일반 사물을 더 찾으려면 `world` 를
  쓰고, 특정 부품·공정 결함처럼 도메인 전용이면 직접 학습시키는 편이 낫다.
  그때도 검출기 인터페이스(`__call__(frame, conf) -> list[Detection]`)만
  맞추면 화면·저장·GUI 는 그대로 쓴다.
